# Internationalization

Omarchy keeps English UI text in the source and loads optional JSON translation catalogs at runtime. Bash commands and the Quickshell desktop share the same locale precedence and catalog manifest.

## Catalogs

Translation catalogs live in `shell/translations/<locale>.json`. Each object maps an exact English source string to its translation. `shell/translations/catalogs.json` is the authoritative list of available locales.

To add a language:

1. Add `shell/translations/<locale>.json` with string keys and values.
2. Add `<locale>` to `shell/translations/catalogs.json`.
3. Run `bash test/shell.d/i18n-test.sh`.

The test requires the manifest to list every catalog exactly once, validates all statically discoverable translation keys, and checks that translated strings preserve their source placeholders.

Locale selection follows `LANGUAGE`, `LC_ALL`, `LC_MESSAGES`, then `LANG`. `LANGUAGE` may contain an ordered colon-separated preference list. A regional locale first tries its full name and then its base language, so `es_AR` tries `es_AR` and then `es`. English is the untranslated source language; reaching `en` stops the search rather than allowing a lower-priority catalog to override it.

Missing manifests, catalogs, keys, malformed JSON, and unavailable `jq` all fall back to the English source text.

## Quickshell

Import `I18n` from `shell/Commons` and use `tr` for ordinary text:

```qml
text: I18n.tr("Hello")
text: I18n.tr("Welcome, %1", [userName])
```

Use `ntr` when a count changes the grammar:

```qml
text: I18n.ntr(count, "%1 item", "%1 items", [count])
```

Both singular and plural source strings need catalog entries. The current API covers the singular/plural rules used by English and Spanish; languages with additional plural categories will require extending the model before adding pluralized strings.

## Bash

Source the shared helper from interactive commands:

```bash
source "$OMARCHY_PATH/default/bash/i18n"
```

Use `omarchy_t` for ordinary strings and `omarchy_nt` for counted strings:

```bash
omarchy_t "Welcome, %1" "$user_name"
omarchy_nt "$count" "%1 item" "%1 items" "$count"
```

Placeholders are numbered from `%1`. Interpolation processes the template once, so placeholder-like text inside an argument is inserted verbatim. A placeholder without a corresponding argument is preserved.

## Source-key guidelines

- Use complete English UI strings as keys; do not introduce symbolic translation IDs.
- Keep command names, routes, filenames, and machine-readable output untranslated.
- Use placeholders for runtime values rather than concatenating translated fragments.
- Use plural APIs for counts instead of forms such as `package(s)`.
- Keep identical concepts on identical source strings so they share one catalog entry.
