# G2 Authenticated Channel Hostile Review

## Decision

PASS after three focused corrections in the D1/D2 seam: the channel now requires a trusted live-generation authority rather than treating its launch-time generation snapshot as permanently current, D2 closes every complete descriptor encoded in a malformed `SCM_RIGHTS` record before rejecting the record, and failed teardown results remain permanently failed instead of becoming successful on a repeated call.

## Seam findings

- Credential and descendant binding: PASS. C7 enables kernel credentials on each private endpoint, compares PID/UID/GID to Bubblewrap's outer child identity, checks the pidfd before and after receive, and D1 checks it again immediately before synchronous dispatch. A descendant cannot replace the payload identity, and a peer exit tears down every role endpoint and resource scope. D1 exposes a read-only `alive()` that is true only while the channel is not failed/terminated and C7's pidfd still reports the exact worker alive; D5 can consume this without acquiring the worker or endpoints. Exit after a fully authenticated packet cannot change that packet's provenance; lifecycle/health policy decides whether an already-started provider operation is cancelled.
- Negotiation and readiness: PASS. Each inherited endpoint has a fixed trusted role and exact single supported role-v1 range. B3 rejects repeated, wrong-role, malformed, or version-disjoint HELLOs. D1 does not publish readiness until control, broker, and render select the same authoritative nonzero generation. Any failure after a partial WELCOME closes all three endpoints, so partial readiness is not reusable.
- Lifecycle generation: PASS after correction. D1 now requires a `GenerationAuthority` at open, rechecks it after aggregate negotiation, before waiting for broker input, and immediately before dispatch. A lifecycle transition from generation 47 to 48 therefore tears down the old channel without calling C4. The production authority must be updated in the same trusted serialized lifecycle domain that publishes activation; it must not be derived from worker payload.
- C4/D4 ingress: PASS. D1 validates envelope role, negotiated version, launch generation, current trusted generation, credentials, and pidfd before its synchronous dispatcher call. C4/D4 retain their own B3 correlation and activation-binding checks. The call-scoped `PacketView` must not be retained beyond `dispatch`.
- Exception containment: PASS. A dispatcher exception is caught at D1, classified as `dispatch_failed`, and causes bounded channel/scope teardown. The adversarial fixture proves the exception cannot unwind through the supervisor.
- Nonblocking response semantics: PASS with an explicit integration condition. C7 uses role-derived envelope-plus-payload caps and `MSG_DONTWAIT`; exact legal broker and render sends are atomic `SOCK_SEQPACKET` datagrams, while `EAGAIN`, interruption, or a nonexact send returns false. The future D4 response pump must treat false as fatal channel loss and must not retry an ambiguous terminal packet. D1 intentionally does not implement that pump.
- Descriptor quarantine: PASS after correction. Receive scans ancillary data before truncation classification, closes every complete delivered descriptor, and then rejects malformed, injected, or truncated control data. Repeated single-descriptor and truncating 24-descriptor floods preserve the broker's complete open-FD count.
- Teardown: PASS after correction. Wrong role/version, stale generation, malformed envelope, credential mismatch, descriptor injection, peer loss before/after readiness, pre-readiness dispatch, rejected dispatch, and thrown dispatch all converge on C7 endpoint closure, pidfd-bounded termination, scope kill if needed, and scope removal. D1 and C7 share a one-way `TerminationState`: only the first caller performs cleanup, an in-progress or failed attempt never reports success, and later calls cannot overwrite a completed failure. D5 can therefore poison/quarantine a worker whenever the first returned teardown result is false without a later false recovery signal.

## Focused evidence

The D1 standalone Debug and Release suites exercise real Bubblewrap plus fake malicious peers. The fully instrumented fake suite runs under ASan/UBSan with leak detection disabled because the launcher helper's seccomp profile is not LSan-compatible. On this development host these credential tests must run outside Codex managed confinement because the outer sandbox denies `SO_PASSCRED` with `EPERM`.

The lifecycle regression negotiates all three roles at generation 47, changes the trusted authority to generation 48 while the worker's generation-47 broker request is pending, and requires fatal `stale_generation`, zero dispatcher calls, and one scope removal. The throwing-dispatcher regression requires the same no-unwind teardown. A focused termination-state regression records failure, attempts to begin again, attempts to overwrite it with success, and requires the result to remain false. A silent peer exits immediately after aggregate readiness; bounded polling requires `alive()` to become false from the pidfd without dispatching a packet, followed by successful scope removal. Existing descriptor-flood, descendant, partial-negotiation, role/version, peer-loss, cap, and saturation cases remain green.
